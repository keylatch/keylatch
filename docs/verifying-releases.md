# Verifying Keylatch Releases

Every Keylatch release is:

- Built reproducibly in GitHub Actions
- Signed with cosign (keyless, via GitHub OIDC → Sigstore transparency log)
- Accompanied by a CycloneDX + SPDX SBOM (generated by syft)
- SHA-256 checksum-verified by the release pipeline

## One-command verification

```bash
keylatch verify --self
```

This checks that the running binary has a valid cosign signature. Requires cosign to be installed.

When installed via Homebrew (or any method that places the binary without an adjacent `.sig` file),
`keylatch verify --self` automatically fetches the matching signature from GitHub Releases.
No manual download of the `.sig` file is required.

## Installing cosign

```bash
# macOS / Linux via Homebrew
brew install cosign

# Go
go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# Full installation docs
# https://docs.sigstore.dev/cosign/installation/
```

## Manual verification steps

For security-conscious users who prefer not to trust the binary to verify itself:

### Step 1: Verify the checksum

Download the release and the checksums file from the [releases page](https://github.com/keylatch/keylatch/releases):

```bash
# Download binary and checksums (adjust for your platform)
curl -LO https://github.com/keylatch/keylatch/releases/download/v<VERSION>/keylatch_<VERSION>_darwin_arm64.tar.gz
curl -LO https://github.com/keylatch/keylatch/releases/download/v<VERSION>/keylatch_<VERSION>_checksums.txt

# Verify SHA-256
sha256sum --check --ignore-missing keylatch_<VERSION>_checksums.txt
```

On macOS, use `shasum -a 256 -c` instead.

### Step 2: Verify the cosign signature

```bash
# Download the .sig file
curl -LO https://github.com/keylatch/keylatch/releases/download/v<VERSION>/keylatch_<VERSION>_checksums.txt.sig

# Verify (keyless — uses Sigstore transparency log)
cosign verify-blob \
  --certificate-identity-regexp '^https://github\.com/keylatch/keylatch/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --signature keylatch_<VERSION>_checksums.txt.sig \
  keylatch_<VERSION>_checksums.txt
```

Expected output:

```
Verified OK
```

### Step 3: Verify the SBOM

```bash
# Download the SBOM and its signature
curl -LO https://github.com/keylatch/keylatch/releases/download/v<VERSION>/keylatch-v<VERSION>.cdx.json
curl -LO https://github.com/keylatch/keylatch/releases/download/v<VERSION>/keylatch-v<VERSION>.cdx.json.sig

# Verify the SBOM signature
cosign verify-blob \
  --certificate-identity-regexp '^https://github\.com/keylatch/keylatch/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --signature keylatch-v<VERSION>.cdx.json.sig \
  keylatch-v<VERSION>.cdx.json

# Inspect the SBOM
cat keylatch-v<VERSION>.cdx.json | jq '.components[].name' | head -20
```

## Release pipeline overview

The Keylatch release pipeline (`.github/workflows/release.yml`) performs these steps in order:

1. **Tests** — full test suite with `-race`
2. **GoReleaser build** — cross-platform binaries and archives
3. **SBOM generation** — `syft` produces CycloneDX JSON and SPDX JSON
4. **Release gates** — docs scan, provider template validation, artifact scan, binary smoke test
5. **cosign signing** — all archives, the checksums file, and the SBOM are signed with `cosign sign-blob --yes` (keyless, GitHub OIDC)
6. **Release manifest** — a JSON manifest of all artifacts is generated and signed
7. **GitHub Release** — all artifacts, SBOMs, signatures, and the manifest are attached

## Transparency log

All keyless cosign signatures are logged to the [Sigstore Rekor transparency log](https://rekor.sigstore.dev/). You can look up any signature:

```bash
rekor-cli search --sha "$(sha256sum keylatch_<VERSION>_checksums.txt | awk '{print $1}')"
```

## Fallback: SHA-256 checksums only

If cosign is not available, verify the SHA-256 checksum as described in Step 1. This provides integrity assurance but not origin assurance (it confirms the file was not corrupted in transit, but not that it was built by the Keylatch pipeline).

## Notes on 0.1.0

The 0.1.0 CLI binaries are cosign-signed via the release pipeline. macOS `.dmg` and Windows `.exe` installer bundles may not yet be Apple/Microsoft code-signed. See [`docs/release-notes/0.1.0-security-note.md`](release-notes/0.1.0-security-note.md) for platform-specific notes.
