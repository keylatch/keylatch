# Verifying Keylatch Releases

A Keylatch release built by the current pipeline (`.github/workflows/release.yml`) is published
only when all of these are attached and verified:

- a keyless [cosign](https://docs.sigstore.dev/cosign/overview/) signature (`.sig`) and
  certificate (`.pem`) for every CLI archive, the checksums file, both SBOMs and the release
  manifest;
- a CycloneDX and an SPDX SBOM (generated by syft);
- SLSA provenance (`keylatch-v<VERSION>-provenance.intoto.jsonl`) covering every CLI archive.

If any of them is missing, the release stays a draft, and Homebrew and Scoop are not updated.

## What each release carries

Older releases were not all built this way. Check the table before relying on a signature.

| Release | Archive and checksums signatures | SBOM | SLSA provenance | Notes |
|---|---|---|---|---|
| v0.9.7 | **none** | **none** | **none** | Published unsigned. See the [v0.9.7 advisory](security/advisory-v0.9.7-unsigned-release.md) |
| v0.9.5 | yes | CycloneDX signed, SPDX unsigned | yes | Linux desktop bundles signed; manifest signature has no certificate |
| v0.9.4 | yes (no `.pem` files) | CycloneDX signed, SPDX unsigned | yes | Verify with the certificate from the Rekor entry |
| v0.9.3 | yes (no `.pem` files) | CycloneDX signed, SPDX unsigned | yes | |
| v0.9.3-alpha.2 | yes (no `.pem` files) | CycloneDX signed, SPDX unsigned | yes | Pre-release |
| v0.9.2 | **none** | **none** | yes | Checksums and provenance only |
| v0.9.1 | **none** | **none** | **none** | Checksums only |
| v0.9.0 | yes | CycloneDX signed, SPDX unsigned | **none** | Desktop installers unsigned |

A release without signatures gives you integrity (the checksum matches) but not origin (that the
Keylatch pipeline built it). Prefer the newest release that has all three columns.

## Manual verification

### Step 1: Verify the checksum

Download an archive and the checksums file from the [releases page](https://github.com/keylatch/keylatch/releases):

```bash
VERSION=0.9.8   # without the leading v
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch_${VERSION}_darwin_arm64.tar.gz"
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-${VERSION}_checksums.txt"

sha256sum --check --ignore-missing "keylatch-${VERSION}_checksums.txt"
```

On macOS, use `shasum -a 256 --check --ignore-missing` instead.

### Step 2: Verify the cosign signature

```bash
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-${VERSION}_checksums.txt.sig"
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-${VERSION}_checksums.txt.pem"

cosign verify-blob \
  --certificate-identity-regexp '^https://github\.com/keylatch/keylatch/\.github/workflows/(release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-(alpha|beta|rc)\.[0-9]+)?|attest-release\.yml@refs/heads/main)$' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --certificate "keylatch-${VERSION}_checksums.txt.pem" \
  --signature "keylatch-${VERSION}_checksums.txt.sig" \
  "keylatch-${VERSION}_checksums.txt"
```

Expected output: `Verified OK`. A valid signature on the checksums file plus a matching checksum
from step 1 verifies the archive. Each archive also has its own `.sig` and `.pem`.

The identity is `release.yml` at a version tag for releases built by the release workflow. It is
`attest-release.yml` on `main` for an older release that was published unsigned and later
rebuilt reproducibly from its tag and signed.

### Step 3: Verify the SLSA provenance

```bash
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-v${VERSION}-provenance.intoto.jsonl"

slsa-verifier verify-artifact "keylatch_${VERSION}_darwin_arm64.tar.gz" \
  --provenance-path "keylatch-v${VERSION}-provenance.intoto.jsonl" \
  --source-uri github.com/keylatch/keylatch \
  --source-tag "v${VERSION}"
```

### Step 4: Verify the SBOM

```bash
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-v${VERSION}.cdx.json"
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-v${VERSION}.cdx.json.sig"
curl -LO "https://github.com/keylatch/keylatch/releases/download/v${VERSION}/keylatch-v${VERSION}.cdx.json.pem"

cosign verify-blob \
  --certificate-identity-regexp '^https://github\.com/keylatch/keylatch/\.github/workflows/(release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-(alpha|beta|rc)\.[0-9]+)?|attest-release\.yml@refs/heads/main)$' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --certificate "keylatch-v${VERSION}.cdx.json.pem" \
  --signature "keylatch-v${VERSION}.cdx.json.sig" \
  "keylatch-v${VERSION}.cdx.json"
```

The SPDX SBOM (`keylatch-v${VERSION}.spdx.json`) is verified the same way.

### Step 5: Verify a desktop installer

When a release ships Linux desktop bundles (`.AppImage`, `.deb`), each has an adjacent `.sig` and
`.pem` and is verified like the checksums file in step 2. This is independent of native Apple or
Windows code signing, which is not in place yet.

## One-command checks from a source checkout

```bash
release-gates/cosign-verify.sh v<VERSION>
release-checks/verify-release-assets.sh <directory with every release asset> v<VERSION>
```

`verify-release-assets.sh` needs cosign and slsa-verifier and fails on any missing or invalid file.

## Release pipeline overview

`.github/workflows/release.yml` runs on a version tag:

1. **Tag check**: the tag's commit must be on `main`, and its required checks must have passed.
2. **Tests**: the full test suite with `-race`.
3. **GoReleaser**: cross-platform archives and container images, and a **draft** GitHub release.
4. **SBOM**: syft writes CycloneDX and SPDX JSON.
5. **Release checks**: docs scan, provider template validation, artifact scan, binary smoke test.
6. **cosign**: every archive, the checksums file and both SBOMs are signed (keyless, GitHub OIDC).
7. **Provenance**: the SLSA generator writes provenance for every archive.
8. **Container**: images are scanned, signed and given an SBOM attestation.
9. **Publish**: every signature and the provenance are verified, assets are attached, and only
   then is the draft published.
10. **Package managers**: the Homebrew tap and Scoop bucket are updated from the signed checksums
    (stable releases only).

## Transparency log

All keyless cosign signatures are logged to the [Sigstore Rekor transparency log](https://rekor.sigstore.dev/):

```bash
rekor-cli search --sha "$(sha256sum "keylatch-${VERSION}_checksums.txt" | awk '{print $1}')"
```
