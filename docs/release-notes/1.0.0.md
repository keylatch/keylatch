# Keylatch 1.0.0

**Release date:** 2025 (target)

Keylatch 1.0.0 is the first stable release. It delivers a complete zero-trust
credential injection pipeline for AI agent environments.

---

## What shipped

### Phase 1 — CLI surface

The full `keylatch` CLI was built and stabilized:

- `keylatch bootstrap` — first-run setup, backend detection, and wizard launch.
- `keylatch connect` — store credentials via any supported backend.
- `keylatch run` — credential-injected subprocess execution with runtime mode
  selection and command allowlist enforcement.
- `keylatch list`, `keylatch describe`, `keylatch doctor` — operational commands.
- Help system (`keylatch help-topic`) with 7 inline reference topics.
- JSON output (`--json`) on all diagnostic commands.

### Phase 2 — Onboarding and wizard

- Browser UI (`keylatch ui`) with a step-by-step first-run wizard.
- Agent profile setup: writes Claude Code and Codex configuration snippets.
- Readiness probe (`GET /v1/health/readiness`) for process managers and
  container healthchecks.

### Phase 3 — Runtime modes and daemon

Four runtime modes delivered:

| Mode | Description |
|------|-------------|
| `gateway_typed` | Typed gateway — strongest isolation (default) |
| `gateway_sdk` | OpenAI-compatible SDK proxy via gateway |
| `direct_brokered` | Ephemeral broker tokens — no gateway required |
| `gateway_proxy` | HTTPS MITM proxy rewriting Authorization headers |

All four modes are permitted in LLM sessions. Raw credential values are never
returned to the agent process in any mode.

The `keylatchd` daemon manages gateway lifecycle, receipt storage, and the
approval inbox.

### Phase 4 — Security guards

- LLM session detection blocks `keylatch get` in agent environments
  (`CLAUDE_CODE`, `CODEX_ENV`, `CREDENTIALS_LLM_SESSION`, `CURSOR_SESSION`).
- Runtime mode guard allows all four modes in LLM sessions; raw credential
  values never reach the agent process in any mode.
- Tamper-evident HMAC-chained audit log at `~/.keylatch/audit.log`.
- Canary leak detection via injected sentinel values in CI.
- Agent-guard shell hook for Claude Code (`contrib/agent-guards/`).

### Phase 5 — Receipt bridge

- Value-free runtime receipts record mode, provider, actor, and exit code after
  every `keylatch run` invocation.
- `GET /v1/receipts` and `GET /v1/receipts/stream` (SSE) expose the receipt log
  to the browser UI.
- Approval inbox: `GET /v1/approvals`, `GET /v1/approvals/stream`, and
  `POST /v1/approvals/{id}` for browser-based approve/deny.

### Phase 6 — Docs site

- Full Mintlify documentation site with Getting Started, Core Concepts,
  Reference, Security, and Release Notes sections.
- OpenAPI 3.1 spec (`docs/api/openapi.yaml`) covering all `keylatchd` routes.
- Spectral lint CI job validates the spec on every pull request.

## Known limitations

- **Provider template signing** (community templates) is planned for a future release.
- **Metrics endpoint** (`/metrics`) returns an empty Prometheus exposition. Full
  OpenTelemetry integration is planned for a future release.

## Upgrading from alpha

If you used a pre-release (alpha) build:

1. Run `keylatch bootstrap` to re-initialize the configuration directory. This
   is non-destructive — existing credentials in your backend are preserved.
2. Run `keylatch doctor` to verify backend availability and daemon health.
3. If the wizard is stuck: set `wizard.completed: true` in
   `~/.keylatch/keylatch.yaml` or open `http://127.0.0.1:7890` and complete the
   remaining wizard steps.
4. Re-run `keylatch agent setup --agent claude-code` to refresh the agent
   profile configuration with 0.1.0 defaults.

## macOS — Gatekeeper workaround

The macOS DMG is **unsigned** in 1.0.0. Apple notarisation (which requires an
$99/yr Apple Developer Program membership) is planned for 1.1.0.

If Gatekeeper blocks the app after mounting the DMG, run the following once:

```bash
xattr -dr com.apple.quarantine /Applications/Keylatch.app
```

Alternatively: right-click the app → **Open** → click **Open** in the dialog.

After the first launch the quarantine flag is cleared and Gatekeeper will not
prompt again.

## Windows — SmartScreen workaround

The Windows installer is **unsigned** in 1.0.0. An EV code-signing certificate
(required by SmartScreen) is planned for 1.1.0.

If SmartScreen blocks the installer:

1. Click **More info** in the SmartScreen dialog.
2. Click **Run anyway**.

Alternatively, verify the binary signature using cosign before running:

```powershell
cosign verify-blob `
  --certificate-identity-regexp="https://github.com/keylatch/keylatch/.github/workflows/release.yml@refs/tags/.*" `
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" `
  --signature keylatch_windows_amd64.zip.sig `
  keylatch_windows_amd64.zip
```

## Verifying release binaries with cosign

All CLI tarballs and checksums are signed using keyless OIDC via
[Sigstore](https://sigstore.dev/). No private key to manage — signatures are
anchored to the GitHub Actions OIDC token.

```bash
cosign verify-blob \
  --certificate-identity-regexp="https://github.com/keylatch/keylatch/.github/workflows/release.yml@refs/tags/.*" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
  --signature keylatch_darwin_arm64.tar.gz.sig \
  keylatch_darwin_arm64.tar.gz
```

Cosign verification instructions and the Rekor transparency log entry are also
available at `https://keylatch.dev/.well-known/cosign.pub`.
